# Frontend Scaffold — Design

## Output

A `frontend/` directory with Dockerfile, `package.json`, `vite.config.js`, `index.html`, and minimal `src/` stubs (`main.jsx`, `App.jsx`); `docker build ./frontend` succeeds and the Vite dev server starts inside the container.

## Story-local design

**Package versions:** React 18 (latest `18.x`), Vite 5 (latest `5.x`). These are not pinned in the plan — use current stable at time of implementation. Lock via `package-lock.json` generated by npm.

**Frontend Dockerfile strategy:** single-stage Node 18 alpine running `vite dev --host 0.0.0.0 --port 3000`. This is a POC evaluated locally — no nginx, no multi-stage build. Simpler and starts faster, which matters for the demo. The `CMD` launches the dev server so `docker compose up` gives the evaluator a live hot-reload app.

**`App.jsx` stub:** returns a bare `<div className="app">Editorial AI</div>`. The full component tree is Phase 5. The stub must be valid JSX that renders without errors so the dev server starts clean.

**`main.jsx` stub:** standard React 18 `createRoot` mount. Nothing unusual.

**`src/` subdirectories to create:** `lib/`, `styles/`, `components/` — all empty (use `.gitkeep` files so git tracks them). Phase 3–5 agents fill them without needing to create the directories.

**`vite.config.js`:** minimal — just the React plugin. No proxy (Phase 6), no aliases needed yet.

**`index.html`:** standard Vite HTML with `<div id="root">` and `<script type="module" src="/src/main.jsx">`. Title: `Editorial AI`.

## Acceptance criteria

- [ ] `frontend/Dockerfile` uses `node:18-alpine`, copies `package.json`, runs `npm install`, and starts `vite dev --host 0.0.0.0 --port 3000`
- [ ] `frontend/package.json` declares `react`, `react-dom` at `^18.x` and `vite`, `@vitejs/plugin-react` as devDependencies
- [ ] `frontend/vite.config.js` imports and applies `@vitejs/plugin-react` — no proxy config (that is Phase 6)
- [ ] `frontend/index.html` has `<div id="root">` and a module script pointing to `/src/main.jsx`
- [ ] `frontend/src/main.jsx` uses `ReactDOM.createRoot` (React 18 API — not the legacy `ReactDOM.render`)
- [ ] `frontend/src/App.jsx` is valid JSX that renders without errors
- [ ] `src/lib/`, `src/styles/`, `src/components/` directories exist (`.gitkeep` files)
- [ ] `docker build ./frontend` exits 0 from `book-publishing-company/`

## Risks

- **React 18 `createRoot` vs legacy `ReactDOM.render`.** Using the old API in `main.jsx` is a common first-draft mistake — it still works but logs a deprecation warning on every hot reload, which looks bad in a demo. The acceptance criterion calls this out explicitly.
- **Vite dev server host binding.** Without `--host 0.0.0.0` the dev server binds to localhost inside the container and is unreachable from the host via Docker port mapping. Easy mistake, caught by the acceptance criterion.
